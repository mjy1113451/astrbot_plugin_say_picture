## 八、经验教训

### 1. 分类规则必须严格执行
标题中的分类关键词是**第一优先级**的分类依据，不应被忽略。

### 2. AI 输出验证失败的处理
```
当 "AI Issue analysis output could not be validated" 出现时：
□ 标记分析失败，不生成后续结果
□ 输出明确的错误信息
□ 避免生成误导性的"无法评估"等结果
```

### 3. 标签推荐是强制要求
每个 Issue 分析必须输出 3-4 个相关标签，不得为空。

### 4. 附件处理是硬性要求
有截图的 Issue，分析结果中必须明确说明是否查看及观察到的关键信息。

### 5. 可行性评估最低标准
即使评估困难，也应提供：
- 涉及的文件/模块
- 初步技术方向
- 需与用户确认的问题

## 九、后续改进建议

1. **分类校验**：增加标题关键词 → 分类的一致性检查
2. **输出验证**：AI 输出格式错误时，应中断分析并明确报错
3. **标签模板**：强制要求输出 3 个标签（来自不同维度）
4. **附件检查表**：截图类 Issue 必须完成附件处理清单
5. **摘要优先**：摘要生成是后续分析的前提，失败时应终止而非继续
