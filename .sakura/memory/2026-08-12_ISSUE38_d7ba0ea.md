## 6. 经验教训

### 6.1 问题模式识别

本次 Issue 体现了 **项目记忆中的"变量覆盖陷阱"模式**：

```
第 249 行: _badge_tw = ...  # 定义
第 312 行: badge_tw = ...   # 错误引用（遗漏下划线）
```

**防范建议**:
- 变量定义后立即使用，减少中间插入其他代码的机会
- 使用 IDE 的"查找引用"功能验证变量一致性
- 统一命名风格（如全局使用下划线前缀约定）

### 6.2 审查遗漏风险

**本次分析未验证**:
- 是否存在其他类似的下划线不一致问题
- `_badge_tw` 在其他位置的引用是否一致
- 是否有其他变量存在相同模式

**改进建议**: 分析报告中可增加"关联检查"项：
```
关联检查:
□ 同作用域内是否还有其他命名不一致
□ 相似变量名(_xxx vs xxx)是否在其他地方也存在
```
