## 6. 经验教训

### 对 UI/图像类 Issue 的分析建议：

1. **截图必须查看**：当前分析基于文字描述，但 Issue 包含截图，应明确说明"已查看附件确认期望位置"

2. **目标位置需具体化**：不能只说"上方"，应给出参考坐标或说明需与用户确认

3. **边界条件考虑**：
   - 文字宽度超出气泡框怎么办？
   - 不同等级数字长度不同时位置如何自适应？

4. **潜在扩展点**：可考虑是否需要配置化，而不仅是硬编码修改

### 未来分析检查清单：
- [ ] 是否查看了所有附件（截图、日志等）？
- [ ] 是否识别了可能的一对多关系（一个 Issue 包含多个功能点）？
- [ ] 可行性评估是否考虑了边界情况和国际化？
- [ ] 是否考虑了可配置性而非纯硬编码？
