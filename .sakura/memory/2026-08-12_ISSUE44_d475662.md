## 6. 经验教训

### 通用要点

1. **断言需有证据**：声称"已修复"时必须提供代码片段或版本信息
2. **PIL Issue 特异性**：ImageDraw 方法名错误容易通过搜索验证，应主动扩展搜索
3. **标签精细化**：通用标签 + 具体技术标签组合效果更好

### 针对本项目的建议

根据代码审查经验库中的 **PIL 绘图类 Bug 审查要点**：

```
□ 排查相似绘图代码是否存在同类参数错误
□ 复制粘贴的代码块需逐一核对参数名
```

本次分析应补充：
- 搜索 `rectangle(` 确认是否还有其他误用
- 检查 LV1-LV99 标签是否有相似阴影绘制代码
- 验证不同 Pillow 版本的 API 兼容性

### 最需改进的点

> **"已修复"的断言必须有可验证的证据支撑**，否则应视为"状态未知"并建议现场核查。
