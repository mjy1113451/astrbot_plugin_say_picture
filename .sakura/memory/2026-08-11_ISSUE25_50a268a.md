## 六、经验教训与改进建议

### 关键发现

| 问题 | 严重程度 | 影响 |
|------|----------|------|
| 未查看/引用附件截图 | **高** | 违反硬性要求，可能导致误判 |
| 置信度普遍偏高 | 中 | 误导任务优先级评估 |
| 标题过度改写 | 中 | 混淆责任边界 |
| 需求模糊未明确标记 | 中 | 后续跟进困难 |

### 改进措施

1. **截图处理强化**：
   ```
   □ 截图是否查看？ → 必须回答
   □ 期望元素位置是否确认？
   □ 修改边界检查是否覆盖？
   ```

2. **模糊需求处理**：
   - 明确标注「**待用户确认**」清单
   - 置信度统一下调 0.10

3. **标题改写规范**：
   - 只做内容补充，不添加分类/优先级前缀
   - 除非原始标题完全无意义才做较大幅度改写

4. **标签数量**：当前 3 个标签合理，但应确保覆盖核心维度（类型+领域+难度）
