## 6. 经验教训

| 维度 | 总结 |
|------|------|
| **置信度一致性** | 检测结果与标签置信度必须保持一致，避免"推断语气+100%置信度"的矛盾 |
| **版本问题识别** | 对于已修复的 bug 类 Issue，应考虑用户如何获知修复版本，建议补充版本/升级说明 |
| **重复 Issue 价值** | 重复 Issue 并非完全无价值，可反映：①问题影响范围 ②用户更新意识不足 ③可能需要优化发版流程 |
| **代码引用规范** | 引用代码位置+commit hash 是最佳实践，增强可信度 |
| **标签体系对齐** | 建议提前了解目标仓库的标签体系（如 `type:`, `stale:`, `priority:` 等前缀规范） |
