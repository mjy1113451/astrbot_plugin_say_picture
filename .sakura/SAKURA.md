# astrbot_plugin_say_picture 项目概述

## 1. 项目简介

astrbot_plugin_say_picture 是一个基于 AstrBot 框架开发的 QQ 机器人插件，核心功能是让机器人能够根据用户 @指令 自动生成和发送表情包图片。该插件通过 OneBot v11 协议与 QQ 平台实现交互，支持群聊和私聊场景下的图片消息发送。

## 2. 技术栈

### 核心框架

AstrBot 框架

AstrBot 是一款模块化的 QQ 机器人框架，支持插件化扩展。开发者可通过编写插件实现自定义功能，框架提供了事件处理、消息解析、配置管理等基础能力。

### 通信协议

OneBot v11 标准

插件遵循 OneBot v11 协议规范，通过调用以下核心 API 实现消息发送功能：

- `send_msg` - 发送消息
- `send_group_msg` - 发送群消息
- `send_private_msg` - 发送私聊消息

### 图像处理

**Pillow (PIL)** - Python 图像处理库

核心功能依赖 PIL 进行图片生成和文本渲染，主要涉及：
- 坐标参数绘图（`draw.text((x, y), ...)`）
- 气泡框绘制和文字定位
- 图片合成与输出

**字体渲染注意事项**：
- 中文字体渲染需要指定字体文件路径
- 需考虑跨平台兼容性：
  - Windows: `C:/Windows/Fonts/simhei.ttf`
  - macOS: `/System/Library/Fonts/PingFang.ttc`
  - Linux: 常见路径或 fontconfig 查询

Python 3.x

项目代码总量约 6145 行，采用 Python 作为主要开发语言，具备良好的跨平台兼容性和丰富的第三方库支持。

### 核心模块说明

**main.py** - 约 6145 行

插件的主逻辑文件，包含消息处理、指令解析、图片生成与发送等核心功能。插件检测用户 @提及 行为，当触发预设指令时执行图片生成流程。

**关键代码位置**：
- 第 121-132 行：字体渲染相关逻辑
- 第 134 行：等级文字（LV100）坐标定位
- 气泡框坐标：起点约 (160, 60)，终点约 (620, 140)

**注意事项**：
- 涉及 PIL 坐标参数调整时需考虑多元素联动
- 不同等级数字长度可能影响文字自适应
- 需考虑多语言文本边界情况

**metadata.yaml**

插件元信息配置，定义插件名称、版本号、作者、依赖项等基本信息，框架通过此文件识别和加载插件。

_conf_schema.json

配置文件的 JSON Schema 定义，描述各配置项的类型、默认值和约束条件，用于配置验证和自动生成配置界面。

config.json

用户运行时配置文件，存储插件的可配置参数，如默认图片地址、发送格式（闪照或普通图片）等。

## 4. 开发约定

### 插件开发规范

基于 AstrBot 框架的插件开发模式，插件需提供标准的元信息配置和入口函数。main.py 中应实现框架定义的事件处理接口，响应用户消息和指令。

### 配置管理约定

插件采用 JSON Schema 规范定义配置结构，配置项包含类型声明、描述说明和默认值。_conf_schema.json 提供了配置验证能力，确保运行时配置的有效性。

### 消息交互约定

遵循 OneBot v11 协议的消息格式，图片消息采用 CQ 码或 URL 方式传输。插件支持普通图片和闪照两种发送模式，可通过配置切换。

### 目录组织约定

.sakura/ 目录用于存放运行时资源，采用 docs、memory、rules 子目录分离不同类型资源。docs/ 存放文档，memory/ 存放运行时数据，rules/ 存放业务规则。

### 许可证遵循

项目采用 AGPL-3.0 许可证，所有分发和修改需遵循开源要求。网络使用场景也需开源相关代码，贡献代码默认接受相同许可证约束。

## 5. Issue 分析经验库

### 分类与优先级指南

| Issue 类型 | 推荐分类 | 优先级参考 |
|-----------|---------|-----------|
| 字体渲染失败 | `bug` | `medium` ~ `high` |
| UI布局调整 | `enhancement` | `low` ~ `medium` |
| 功能增强请求 | `enhancement` / `feature-request` | 根据影响范围定 |
| 中文/国际化问题 | `bug` + `font`/`i18n` 标签 | `medium` 起 |

**经验**：
- 应独立分析后给出分类判断，不应完全沿用原标签
- 图片类 Issue 应查看附件截图，结合视觉信息判断

### 标签推荐策略

**必检标签**：
- `bug` - 功能缺陷
- `enhancement` - 功能改进
- `font` - 字体相关问题
- `UI` / `user-interface` - 界面相关
- `beginner` / `good-first-issue` - 适合新人的简单改动

**置信度评估**：
- 仅基于标题：0.7 ~ 0.85
- 结合代码分析：0.85 ~ 0.95
- 图片 Issue 应适当降低置信度（考虑信息损耗）

### 可行性评估要点

**代码定位**：
- 使用具体行号引用，增强可信度
- 引用代码片段时标注来源

**跨平台兼容性**（字体相关必须考虑）：
- Windows 系统字体路径
- macOS 系统字体路径
- Linux fontconfig 查询方案

**边界情况检查**：
- [ ] 文字宽度超出容器怎么办？
- [ ] 多语言/不同文本长度如何适配？
- [ ] 修改是否影响其他元素布局？
- [ ] 是否需要配置化而非硬编码？

**降级策略**：
- 摘要生成失败时，使用关键词提取备用方案
- 协议标签需过滤（http://, javascript: 等）

### 重复检测建议

基于关键词组合检索（如 `LV100` + `气泡框` + `位置调整`），一般独特性明显时可跳过详细检索。
