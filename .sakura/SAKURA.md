## 一、字体下载子系统审查（PR #27 核心教训）

### 1.1 问题发现

PR #27 的增量审查仅聚焦"排版优化"，遗漏了**引入的新子系统**：`_load_cn_font()` 函数包含网络下载和临时文件管理。

**关键遗漏**：
- 网络下载的超时设置
- 下载失败时的降级路径
- 临时目录的清理机制
- 多线程场景下的缓存安全性

### 1.2 下载类操作必查清单

```
□ HTTPS 链接是否存在
□ 是否有完整性校验（hash/签名）
□ 是否有超时机制
□ 下载失败时的降级/报错策略
□ 临时文件清理机制
□ 磁盘空间不足的处理
```

### 1.3 全局状态修改检测

**新增外部依赖必查清单**：
```
□ 是否修改了模块级全局变量
□ 是否调用了 setdefaulttimeout、setrecursionlimit 等全局设置函数
□ 是否使用全局超时而非单次请求超时（后者更精确）
□ 是否修改了环境变量或全局配置
□ 变更是否会传递到其他代码路径
```

**超时设置最佳实践**：
```python
# ❌ 全局设置，影响所有请求
socket.setdefaulttimeout(30)

# ✅ 单次请求设置，精确控制
urllib.request.urlopen(url, timeout=30)
```

### 1.4 多级回退链路验证

当代码存在 3 级及以上回退时，必须逐级验证：
```
□ 每级失败是否被 try-except 捕获？
□ 每级失败是否记录日志？
□ 最终兜底是否保证程序可继续运行？
□ 降级链路是否完整（不会中途静默失败）
```

### 1.5 临时文件审查要点

```
□ 使用后是否显式关闭
□ 是否设置了合理的生命周期
□ 长期运行进程是否会导致 /tmp 膨胀
□ 异常路径下是否也会清理
□ 是否依赖 delete=True（不足以保证清理）
```

### 1.6 增量审查的正确边界

```
quick 策略下：
- 仍聚焦增量功能本身
- 但需明确标注"未审查区域"
- 增量引入新子系统（网络/文件/线程）时，应触发完整审查
- 不应将"功能实现正确"等同于"代码健壮性合格"
```

### 1.7 字体下载/缓存场景审查经验

1. 优先使用系统字体，避免网络下载
2. 若必须下载，验证 SHA256
3. 使用 `shutil.rmtree` 清理缓存，而非依赖 `delete=True`
4. 多线程场景加锁或使用单例模式

## 三、Issue 分类与标签规范

### 3.1 分类准确性要求

**常见错误**：将 UI 样式问题分类为 `other` 或 `bug`

| 问题类型 | 正确分类 | 说明 |
|----------|----------|------|
| 字体显示、样式不一致 | `enhancement` 或 `UI` | 功能未达期望，非程序错误 |
| 气泡框排版问题 | `UI` 或 `enhancement` | 视觉调整类 |
| 程序崩溃、功能完全不工作 | `bug` | 明确的功能失效 |

**区分标准**：
- `bug`：程序崩溃、功能完全不工作
- `enhancement`：功能未达到期望体验、体验优化

### 2.2 标签推荐（强制要求）

**所有 PIL/绘图类 Issue 必须包含**：

| 标签 | 置信度 | 理由 |
|------|--------|------|
| `PIL/pillow` | 0.85+ | 字体渲染依赖 pillow |
| `layout` | 0.80+ | 涉及排版/布局调整 |
| `style` | 0.75+ | 视觉样式问题 |
| `beginner` | 0.70+ | 纯参数调整，适合新手 |

**字体类 Issue 额外标签**：
- `font` | 0.85+
- `rendering` | 0.80+

### 2.3 标签-分类一致性

| 分类 | 常见矛盾标签 | 处理方式 |
|------|-------------|----------|
| `enhancement` | `bug` | 必须移除 `bug` 标签 |
| `bug` | `enhancement` | 可保留，两者是不同的维度 |

### 2.4 Issue 分析流程失败处理

| 情况 | 操作 |
|------|------|
| AI 输出无法通过验证（如缺少 `</SUGGESTED_TITLE>`） | ❌ 不得使用"无法评估"等模糊结论；✅ 应重试分析或标记"分析失败，待人工处理" |
| 原标题异常（< 5 字或无意义如"。"、"bug"、"问题"） | ✅ 必须改写为描述性标题，不得标记"无建议" |

## 三、截图引用与标题改写规范

### 3.1 截图查看清单（PIL/UI 类 Issue 必查）

```
截图查看结果：
- 观察到的布局特征：头像位置、气泡框间距、整体紧凑程度
- 与当前实现的差异：当前参数 vs 期望参数对比
- 修改边界：需覆盖截图中的所有元素位置
```

**禁止表述**：仅说"已查看截图"而不描述内容。
**最低要求**：即使只描述"截图中用户指出了字体位置"也比完全不提及好。

### 3.2 标题改写规范

| 情况 | 操作 |
|------|------|
| 原标题 ≥ 5 字且清晰 | 不改写 |
| 原标题 < 5 字或无意义（如"bug"、"问题"、"逗号"） | 改写为描述性标题 |
| 任何情况 | ❌ 禁止添加 `[分类]` / `[优先级]` 前缀 |

**越权示例**（严重违规）：
```
❌ 错误：[bug][medium] 生成图片字体与聊天框显示不一致
✅ 正确：生成图片字体与聊天框显示不一致
```

### 3.3 可行性评估要求

```
❌ 禁止："无法评估"
✅ 正确：根据描述至少判断"高/中/低工作量"和涉及模块
```

## 十二、修复类 PR 专项审查

### 12.1 修复验证 ≠ 根因验证

| 验证类型 | 做法 | 目的 |
|----------|------|------|
| 修复验证 | 确认 `badge_tw` 改为 `_badge_tw` | 确保修改已生效 |
| 根因验证 | 搜索所有 `badge_tw` 引用，排查遗漏 | 防止同类问题残留 |

### 12.2 修复类 PR 审查清单

```
□ 问题是否只出现在这一处？
□ 是否存在同类问题的扩散检查（如变量名一致性）？
□ 修复是否引入新变量名的一致性问题？
□ 搜索变更涉及的所有相关标识符
```

### 12.3 变量覆盖陷阱识别

```python
# ❌ 隐蔽陷阱：同一作用域内重复赋值
badge_tw = font_small.getbbox(...)  # 第 1 处
# ... 省略若干行 ...
badge_tw = badge_bb[2] - badge_bb[0]  # 第 2 处，覆盖旧值

# ✅ 推荐：使用不同变量名或重构
badge_tw_from_font = font_small.getbbox(...)
# ... 
badge_tw_calculated = badge_bb[2] - badge_bb[0]
```

## 十三、布局变更专项审查（增强版）

### 13.1 强制升级条件

**以下情况必须升级审查策略，不得降级为 Quick/Fast**：
- 涉及坐标计算、对齐方式变化
- 包含 ≥5 步数学运算
- 涉及多元素联动（头像、气泡、三角指针）

### 13.2 数值代入验证（必须执行）

```
□ 代入至少 3 组具体数值验证坐标计算
□ 检查气泡高度变化时（0、正常、极端）的行为
□ 验证相关联的 x/y 坐标同步更新（如三角指针）
```

**示例**：
```
原逻辑：canvas_h=200, avatar_size=90, bubble_y0=50
  → avatar_y = (200 - 90) // 2 - 8 = 46

新逻辑：bubble_y0 - 10 = 50 - 10 = 40

差值：6 像素（需确认是否在视觉容忍范围内）
```

### 13.3 三角指针专项检查

等腰三角形的位置变化涉及两个坐标（x 和 y），需同步验证：
```
□ 三角指向是否仍指向目标元素中心
□ 等腰三角形顶点位置变化是否影响视觉
□ 坐标联动：头像尺寸变化后三角坐标是否同步调整
```

## 十四、技术性失败处理规范

### 14.1 技术性失败 ≠ 无法评估

| 类型 | 定义 | 正确处理 |
|------|------|----------|
| 技术性失败 | AI 输出格式校验失败、解析异常 | 记录根因，尝试重试或标记"待人工处理" |
| 无法评估 | 经过重试仍无法判断 | 明确说明原因，保留判断权 |

### 14.2 分析流程失败处理

| 情况 | 操作 |
|------|------|
| AI 输出无法通过验证（如缺少 `</SUGGESTED_TITLE>`） | 记录错误原因，**尝试重试**，若仍失败标记"待人工处理" |
| 格式解析失败（如方括号标签嵌套） | 基于摘要内容重新评估，而非终止 |

### 14.3 质量门禁

```
□ 标签为空时应触发警告而非静默通过
□ 分类为 enhancement 时必须移除 bug 标签
□ 优先级应尊重用户自评（除非明显不合理）
```

## 十六、Quick 模式决策树（增强版）

### 16.1 升级判断标准

```

├─ 否 → 升级完整审查
└─ 是 → Quick 审查
    └─ 但需验证：无复杂计算链路
```

### 16.2 Quick 模式禁止项

以下情况无论行数多少，均视为"复杂逻辑"：
```
□ 涉及数学公式的变更
□ 涉及多元素坐标联动
□ 涉及字符串宽度/高度计算（PIL text bbox）
□ 新增网络/文件/线程操作
```

### 16.3 Quick 模式评分建议

当变更包含复杂计算时：
```
□ 9/10 评分需明确说明"扣 1 分"的原因
□ 建议补充数值代入验证过程
□ 边界情况测试说明
```
