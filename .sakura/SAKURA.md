# 项目概述文档

## 项目简介

astrbot_plugin_say_picture 是一个让 AstrBot QQ 机器人能够发送图片消息的插件。当检测到 @某用户 说特定指令时，插件会自动生成表情包或发送预设图片。基于 AstrBot 框架开发，通过 OneBot v11 协议实现与 QQ 平台的无缝交互，为群聊和私聊场景提供丰富的图片消息服务。

## 技术栈

本项目的技术选型简洁高效，主要围绕以下技术构建：

**编程语言**：Python 3，作为 AstrBot 插件生态的主流开发语言，拥有丰富的库支持和活跃的社区。

**核心框架**：AstrBot 插件系统，这是项目运行的基础平台，提供了插件加载、事件处理、配置管理等核心功能。

**通信协议**：OneBot v11 标准，这是 CQHTTP 的继承标准，定义了机器人与 QQ 平台之间的通信规范。通过 send_msg、send_group_msg、send_private_msg 等 API 实现消息的发送功能。

**兼容客户端**：项目兼容所有符合 OneBot 标准的实现端，包括 go-cqhttp、Lagrange.OneBot 和 NapCat 等主流 QQ 协议端，确保了部署的灵活性。

**许可证**：GNU Affero General Public License v3.0 (AGPL-3.0)，这是一款严格的开源许可证，要求衍生作品也必须开源发布。

## 项目结构

项目的目录结构设计清晰，遵循 AstrBot 插件的标准规范：

```
astrbot_plugin_say_picture/
├── .gitignore          # 版本控制忽略规则
├── .sakura/
│   ├── docs/          # 项目文档目录
│   ├── memory/        # 运行时记忆数据存储
│   └── rules/         # 规则配置文件
├── LICENSE             # AGPL-3.0 开源许可证全文
├── README.md           # 项目说明与使用指南
├── _conf_schema.json   # 配置项结构定义（schema）
├── config.json         # 用户配置文件
├── main.py            # 插件核心逻辑主文件
└── metadata.yaml      # 插件元信息描述
```

**核心模块说明**：

main.py 是插件的主逻辑文件，承载了指令监听、图片生成与发送等核心功能的实现。代码规模约 6145 行，表明这是一个功能相对完善的插件，而非简单的示例代码。

metadata.yaml 负责定义插件的元信息，包括插件名称、版本号、作者、依赖项等，这些信息被 AstrBot 用于插件市场的展示和依赖管理。

_conf_schema.json 与 config.json 形成配置的双层架构，前者定义配置项的类型、默认值和描述，后者是实际生效的配置文件，用户可根据 schema 定义进行自定义调整。

.sakura/ 目录是 AstrBot 插件的标准数据目录，其中 docs 存放文档、memory 存储运行时的持久化数据、rules 放置规则配置。

## 开发约定

通过分析项目结构和代码组织方式，可以推断出以下开发规范：

**配置管理规范**：项目采用 schema 驱动的配置管理模式。开发者通过 _conf_schema.json 定义所有可配置项的结构和约束，用户则在 config.json 中提供实际值。这种设计确保了配置的规范性和可验证性，降低了用户配置错误的风险。配置项包括 default_image_url（默认图片 URL）和 send_format（发送格式，支持 flash 或 normal 两种模式）等。

**插件元信息规范**：所有插件元数据集中管理于 metadata.yaml 文件中，包括插件标识、版本、作者、依赖关系等信息。这种集中管理方式便于 AstrBot 进行插件识别、版本控制和依赖解析。

**目录结构规范**：项目遵循 AstrBot 的标准目录约定，.sakura/ 子目录用于存放运行时数据和规则，这与 AstrBot 框架的设计理念保持一致，便于框架统一管理和数据持久化。

**开源许可规范**：项目采用 AGPL-3.0 许可证，这是-copyleft 类型的开源许可证。任何基于本项目的衍生作品都必须开源发布，且如果通过网络提供服务，源代码也必须公开可获取。开发者在集成此插件到自己的项目时需要特别注意这一许可要求。

**API 使用规范**：项目通过 OneBot v11 协议与 QQ 平台交互，遵循标准的 API 调用规范。这确保了插件能够兼容所有符合 OneBot 标准的 QQ 协议实现端，具有良好的可移植性。

**协作流程规范**：README 中描述了标准的 GitHub 协作流程，包括 Fork、创建特性分支、提交更改、推送分支和提交 Pull Request 的完整流程。对于希望参与项目贡献的开发者提供了清晰的指引。
