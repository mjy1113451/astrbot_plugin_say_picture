# 代码审查经验总结

> 累计反思 18 次

## 一、分类与优先级评估

### 1.1 分类规则（核心）
| 场景 | 处理方式 |
|------|----------|
| 标题含 `[enhancement]` / `[bug]` 等关键词 | **直接采用**，不另行判断 |
| 标题含分类词却被分为其他类别 | 严重错误，违反分类规则 |
| 标题无意义/异常 | 标注"标题异常，基于正文分析"，并说明依赖了哪些内容 |

### 1.2 优先级独立判断
- **不盲目采纳作者自评**：纯 UI 调整 + 极简单修改 → 可降级至 `low`
- 应基于影响范围独立评估，而非直接沿用原标签
- 功能受影响时维持作者评级，影响核心功能时可升级

---

## 二、标签推荐质量

### 2.1 数量要求
- **强制要求**：每个 Issue 必须输出 3-4 个标签，**不得为空**
- 标签应来自不同维度（类型 + 领域 + 技术栈）

### 2.2 标签体系（本项目）
| 标签 | 适用场景 | 置信度参考 |
|------|----------|-----------|
| `enhancement` | 功能改进类 | 0.85+ |
| `bug` | 错误修复类 | 0.90+ |
| `image-generation` | 涉及图片生成的 Issue | **项目本身是图片插件，应提升至 0.95** |
| `UI` / `display` | UI/布局调整类 | 0.80 |
| `font` / `text-rendering` | 字体/文字渲染相关 | 0.80 |
| `PIL` / `pillow` | 涉及 PIL 绘图修改 | 0.85 |
| `style` / `visual` | 样式/视觉效果 | 0.75 |

### 2.3 置信度调整
- **模糊需求**：整体置信度下调 0.05-0.10
- 图片 Issue 视觉解读不确定性：下调 0.05

---

## 三、可行性判断质量

### 3.1 最低标准
即使评估困难，也应提供：
```
□ 涉及文件：xxx.py（模块名）
□ 涉及组件：PIL 绘图 / 气泡框布局 / 字体渲染
□ 初步技术方向
□ 需与用户确认的问题清单（明确标注）
```

### 3.2 深度要求
| 评估项 | 要求 |
|--------|------|
| 代码定位 | 引用具体代码片段，而非仅说"某行" |
| 方案描述 | 给出伪代码或计算公式 |
| 工作量 | 需对比现有代码规模估算，说明依据 |
| 风险识别 | 提及边界情况（如字体回退、API 弃用） |

### 3.3 边界检查（PIL/坐标类 Issue）
```
□ 水平边界：文字宽度是否超出容器
□ 垂直边界：元素高度变化是否影响间距
□ 对齐关系：修改后是否保持元素对齐
□ 坐标基准：是否基于固定尺寸气泡框
```

### 3.4 行号一致性
- 摘要与分析结果的行号描述必须一致
- 存在差异时应标注"代码版本差异，请确认实际行号"

---

## 四、重复检测准确性

### 4.1 记录要求
必须明确记录检索策略：
```
检索词：关键词1 + 关键词2
检索范围：astrbot_plugin_say_picture 仓库全量 Issue
结果：X 条相关 / 无重复
```

### 4.2 检索策略建议
- LV100 相关 Issue 检索：`LV100` + `字体` + `字号/大小`
- 布局样式类检索：`layout` + `样式` + `排版` + `气泡`

---

## 五、标题改写适当性

### 5.1 改写原则
| 情况 | 建议 |
|------|------|
| 原标题已清晰 | **不做改写**，或仅补充分类标签 |
| 原标题无意义 | 可较大幅度改写，但**不预设分类** |
| 模糊需求 | 保留内容，标注"待用户确认" |

### 5.2 禁止事项
- **禁止添加预设分类**：不应在标题中擅自添加 `[enhancement]` / `[bug]` 等标签
- **禁止为改写而改写**：无实质改进时保持原样

---

## 六、附件处理（硬性要求）

### 6.1 强制检查清单
```
□ 截图是否查看？ → 必须明确回答
□ 期望元素位置是否从截图确认？
□ 修改边界是否覆盖截图中的关键区域？
```

### 6.2 违规后果
- 未查看截图 → 违反硬性要求，分析结果可能严重偏差
- 未引用截图内容 → 分析缺乏依据

---

## 七、AI 输出验证与错误处理

### 7.1 验证失败处理
当出现 `AI Issue analysis output could not be validated` 时：
```
□ 标记分析失败，不生成后续结果
□ 输出明确的错误信息
□ 避免生成误导性的"无法评估"结果
```

### 7.2 摘要优先级
- 摘要生成是后续分析的前提
- 摘要失败时应**终止分析**而非继续

---

## 八、项目特定注意事项

### 8.1 PIL 版本差异
- `ImageFont.getsize` 在新版本已弃用，应使用 `.getbbox()`
- 不同版本 API 可能有变化

### 8.2 字体回退机制
- 必须考虑用户系统字体差异（Windows/macOS/Linux）
- 字体路径跨平台兼容性

### 8.3 坐标固定性
- 气泡框坐标基于固定画布
- 调整时需重新计算所有相对位置

---

## 九、评分标准速查

| 维度 | 评分 | 说明 |
|------|------|------|
| 分类准确性 | 8-10 | 正确采用标题分类词 |
| 标签质量 | 7-10 | 3-4个标签，覆盖多维度 |
| 可行性判断 | 7-10 | 代码引用 + 边界检查 |
| 重复检测 | 7-10 | 记录检索策略 |
| 标题改写 | 7-10 | 适度改写，不越权 |
| 附件处理 | 10 | 必查截图并引用 |
