# AstrBot 图片生成插件 Issue 分析经验总结

累计反思 12 次

---

## 一、项目概述

- **项目类型**：AstrBot 插件，聊天截图转表情包生成
- **核心技术**：PIL 绘图、字体渲染、坐标布局
- **Issue 特点**：以 UI 调整、功能增强为主，少量 bug

---

## 二、分类与优先级

### 2.1 分类规则
| 标题关键词 | 应分类为 |
|-----------|---------|
| `[bug]` | `bug`（**必须**，不能误分为 `other`） |
| `[enhancement]` | `enhancement` |
| `[feature]` | `feature` |
| 无关键词 | 基于内容判断 |

### 2.2 优先级参考
- `high`：核心功能崩溃、影响所有用户
- `medium`：UI 调整、非阻塞性问题
- `low`：美化优化

---

## 三、标签体系（必须使用）

### 3.1 常用标签
| 标签 | 适用场景 | 置信度参考 |
|------|---------|-----------|
| `bug` | 功能缺陷 | 0.90+ |
| `enhancement` | 功能改进 | 0.85 |
| `feature` | 新功能请求 | 0.85 |
| `font` / `chinese` | 字体/中文相关 | 0.85 |
| `UI` / `display` | 界面布局调整 | 0.85 |
| `image-generation` | 图片生成相关 | 0.80 |
| `beginner` / `good-first-issue` | 简单改动 | 0.70 |

### 3.2 标签提取降级策略
> 标签提取失败时 → **不能放弃**，应依赖摘要关键词补充标签

---

## 四、可行性判断

### 4.1 必要检查项
```
□ 代码定位：引用具体文件行号
□ 参数明确：给出具体坐标/数值建议
□ 需与用户确认的内容明确标注
□ 配置化可能性评估
□ 工作量估算
```

### 4.2 跨平台风险（字体/路径类 Issue）
- Windows：`C:/Windows/Fonts/simhei.ttf`、`msyh.ttc`
- macOS：`/System/Library/Fonts/PingFang.ttc`
- Linux：fontconfig 查询

### 4.3 UI/坐标类风险检查
| 风险点 | 评估内容 |
|--------|---------|
| 文字宽度 | 字体放大后是否超出容器边界 |
| 元素间距 | 调整后是否与其他元素重叠 |
| 气泡框尺寸 | 坐标是否基于固定尺寸 |
| 国际化 | 其他语言文本长度差异 |

---

## 五、附件处理（硬性要求）

**有截图时必须查看并引用具体位置**，不得遗漏。

```
□ 截图是否查看？
□ 期望位置是否从截图确认？
□ 边界检查：修改后元素是否超出容器？
□ 视觉一致性：间距是否协调？
```

---

## 六、置信度管理

| 依据 | 置信度范围 |
|------|-----------|
| 仅标题关键词 | 0.70-0.85 |
| + 代码依据 | 0.85-0.90 |
| + 截图确认 | 0.90-0.95 |
| **图片 Issue 视觉解读存在不确定性，置信度应适度下调** |

---

## 七、重复检测

- 使用关键词组合检索（如 `LV100` + `位置` + `字体`）
- UI 位置调整类 Issue 通常独特
- 补充说明检索策略以增强可追溯性

---

## 八、常见错误与改进

| 错误 | 改进 |
|------|------|
| 分类为 `other` | 标题含分类词时应直接采用 |
| 标签仅 1 个 | 应包含 3-4 个标签（enhancement, UI, font） |
| 未查看截图 | **必须查看**附件图片 |
| 置信度 0.95 | 图片 Issue 应下调至 0.85 |
| 未评估边界风险 | 补充文字宽度、元素间距检查 |

---

## 九、仓库特定模式

| 模式 | 注意事项 |
|------|---------|
| PIL 绘图坐标调整 | 考虑元素间对齐关系，相对/绝对坐标 |
| 文本渲染 | 评估字体大小对整体布局的影响 |
| 字体问题 | 考虑跨平台兼容性、字体回退机制 |
| 气泡框布局 | 坐标基于气泡框顶部，需确认气泡框尺寸是否固定 |
