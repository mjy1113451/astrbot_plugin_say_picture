## 一、增量审查规范

### 1.1 新增代码引入新子系统必查

**识别标准**：当增量代码包含以下任一特征时，视为"隐藏子系统"，需完整审查：
- 网络操作（下载、API 调用）
- 文件系统操作（非简单读写）
- 线程/并发相关
- 新增函数 >30 行

**必查清单**：
```
□ 新函数是否被正确调用
□ 新函数自身的异常处理
□ 新函数引入的资源（网络/文件）生命周期
□ 新函数与现有代码的交互边界
```

### 1.2 外部依赖引入必查规则（新增）

当代码包含网络下载、API 请求时，必须审查：
```
□ 超时设置（建议 timeout=30s）
□ 下载失败降级路径
□ 完整性校验（hash/签名）
□ 重试/幂等性处理
□ SSL/证书验证
```

### 1.3 临时资源生命周期规则（新增）

当代码创建临时文件/目录时，必须审查：
```
□ 临时文件创建位置是否合理
□ 是否注册清理回调（cleanup）
□ 异常路径下是否泄漏
□ 长期运行进程是否会累积垃圾
□ 进程终止时的清理机制
```

### 1.4 增量审查评分修正

| 场景 | 评分修正 |
|------|----------|
| 增量引入新子系统 | 原评分 -2（安全性/健壮性未审查） |
| 仅聚焦功能实现 | 需明确标注"未审查区域" |

## 二、Issue 分析规范

### 2.1 截图必查流程

**所有涉及 UI/样式的 Issue 必须：**
1. 查看截图中的文字样式、间距、颜色等视觉特征
2. 对比描述中的期望效果
3. 在分析中引用截图内容

### 2.2 PIL 绘图类 Issue 必含标签

本仓库所有绘图类 Issue 必须包含：
| 标签 | 置信度 | 理由 |
|------|--------|------|
| PIL/pillow | 0.85+ | 字体渲染属于绘图核心问题 |
| layout | 0.80+ | 涉及排版/样式一致性 |
| style | 0.75+ | 字体外观/颜色调整 |
| beginner | 0.70+ | 纯参数调整，适合新手 |

### 2.3 分类规范

**禁止使用 `other` 作为分类**，应明确归类：
| 问题类型 | 分类建议 |
|----------|----------|
| 字体/文字渲染 | enhancement 或 bug |
| 气泡框排版 | UI |
| 头像位置 | UI |
| 颜色/渐变 | style |
| 性能问题 | bug |

**bug vs enhancement 区分：**
- `bug`：程序崩溃、功能完全不工作
- `enhancement`：功能未达期望、体验优化

### 2.4 标签-分类一致性

标签必须与分类逻辑自洽：
- 若分类改为 `enhancement`，移除 `bug` 标签
- 若分类为 `bug`，确保是功能失效而非体验问题

### 2.5 标题改写规范

**改写条件**：原标题 < 5 字或无意义（如仅 "bug"/"问题"）

**改写规则**：
- ✅ 可改写为描述性标题
- ❌ **禁止添加分类前缀**（如 `[bug][medium]`）
- ❌ 越权前缀是红线

### 2.6 重复检测记录规范

必须记录：
```
- 检索词：["字体", "样式", "聊天框", "不一致"]
- 检索范围：仓库全量 Issue
- 结论：不重复（#26 为布局问题，与字体独立）
- 置信度：0.85
```

## 三、敏感操作边界检查

适用于所有涉及资源获取/释放的操作：

```
□ 资源获取：是否有竞态条件
□ 资源释放：异常路径是否也会释放
□ 网络操作：超时、重试、失败处理
□ 文件操作：权限、空间、路径遍历
□ 配置依赖：硬编码值是否有配置化需求
```

## 四、评分与决策一致性

| 评分 | 决策 | 问题数 | 一致性 |
|------|------|--------|--------|
| 6/10 | request_changes | 1 个文字溢出 | ⚠️ 可能不一致（遗漏更多中高风险） |

**教训**：评分应反映实际发现的问题数量和严重程度。

## 五、代码模式识别

### 5.1 字体下载模式

```python
# 搜索链模式（成熟但需审查）
paths = [path1, path2, ...]
for path in paths:
    if os.path.exists(path):
        return path

# 回退下载模式（安全敏感）
if not found:
    download_from_github()
    cache_in_tempdir()
```

### 5.2 临时文件模式风险

```python
# delete=True 不等于清理缓存目录
temp_file = NamedTemporaryFile(delete=True)
# 风险：文件关闭时删除，但缓存目录下文件不会被清理

# 路径拼接错误
font_path = os.path.join(os.path.dirname(tempfile.gettempdir()), ...)
# 错误：gettempdir() 已是路径，再 dirname() 会上一级
```

### 5.3 字体场景审查要点

1. 优先使用系统字体，避免网络下载
2. 若必须下载，验证 SHA256
3. 使用 `shutil.rmtree` 清理缓存
4. 多线程场景加锁或使用单例模式
