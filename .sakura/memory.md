## 核心经验

### 1. 审查深度原则

| 场景 | 审查策略 | 说明 |
|------|----------|------|
| 首次全量审查 | **Full**（强制） | 必须记录项目架构、入口、潜在风险区 |
| 后续增量审查 | Quick/Fast | 聚焦变更本身 |
| 布局/坐标变更 | **强制升级** | 即使行数少，也需完整审查 |
| 涉及坐标计算 | **强制数值代入验证** | 至少 3 组测试用例 |

**硬性约束**：首次全量审查策略不得降级为 Quick/Fast。

### 2. 审查质量维度

- **覆盖度**：是否遗漏检查项（坐标计算正确性、边界情况）
- **准确度**：评分与决策是否一致
- **完整性**：变更意图理解 + 实现细节验证

### 3. 修复类 PR 专项检查

```
□ 问题是否只出现在这一处？（同类问题排查）
□ 是否存在变量名一致性问题？
□ 修复验证 ≠ 根因验证——需搜索所有相关标识符
```

## 布局/UI 变更审查要点

### 坐标计算验证清单

- [ ] 代入至少 3 组具体数值验证坐标计算
- [ ] 检查气泡高度变化时（0、正常、极端）的行为
- [ ] 验证相关联的 x/y 坐标同步更新（如三角指针）
- [ ] 极端长度测试：单字符、正常长度、超长文本
- [ ] 不同头像尺寸下的坐标验证

### 关键教训

> **"小改动" ≠ "无风险"**：坐标变更可能引发级联影响（头像、三角、文字三者联动）。

## 代码模式观察

### PIL 图片合成项目特征

| 特征 | 审查关注点 |
|------|------------|
| 尺寸预计算模式 | 先测量 bbox，再分配画布，需验证绘制位置一致性 |
| 变量覆盖陷阱 | 同一作用域内重复赋值易引发隐蔽 bug |
| 硬编码魔法数字 | 内边距、圆角等应识别"看似可配置"的常量 |
| 复制粘贴风险 | 绘图代码块需逐一核对参数名 |

### 典型问题模式

```python
# 变量名重复 + 覆盖
badge_tw = font_small.getbbox(...)  # 第 1 处
# ... 省略若干行 ...
badge_tw = badge_bb[2] - badge_bb[0]  # 第 2 处，覆盖旧值
```

## 审查方法论

### Quick 模式决策树（增强版）

```
行数 ≤ 30?
├─ 否 → 升级完整审查
└─ 是 → Quick 审查
    ├─ 验证：无复杂计算链路？
    └─ 若包含 ≥5 步数学运算 → 降级评分或补充测试说明
```

### Issue 分析要点

| 维度 | 检查项 |
|------|--------|
| 分类准确性 | bug/enhancement 等核心标签 |
| 优先级 | **独立评估**，不被动采纳原标题 |
| 标签质量 | 识别技术栈标签（PIL 等） |
| 可行性 | 一致性验证（对比同文件相似代码） |
| 同类问题排查 | typo/bug 应顺带检查类似问题 |

## 规范完善建议（已采纳）

### 新增规则

1. **首次全量审查特别要求**
   - 审查策略不得降级
   - 必须记录：项目核心功能、入口、潜在风险区
   - 变更排查范围应覆盖所有相关标识符

2. **布局变更强制审查**
   - 涉及坐标计算/对齐方式变化，无论行数多少，均视为复杂逻辑

3. **PIL 绘图类 Bug 审查要点**
   - 排查相似绘图代码是否存在同类参数错误
   - 复制粘贴的代码块需逐一核对参数名

## 经验教训摘要

| # | 教训 | 行动项 |
|---|------|--------|
| 1 | 一致性 ≠ 正确性 | 坐标计算需额外验证 |
| 2 | 变量覆盖是隐蔽陷阱 | 标注同一作用域内重复赋值风险 |
| 3 | Quick 模式边界条件执行不一致 | 规范标注"强制"必须被执行 |
| 4 | 优先级被动采纳倾向 | 独立评估，基于影响范围 |
| 5 | 无评论策略导致知识零沉淀 | 简短确认注释也有价值 |
