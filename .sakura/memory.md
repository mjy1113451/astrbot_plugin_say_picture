# 代码审查经验总结

> 累计反思 29 次

## 一、增量审查核心规范

### 1. 新增外部依赖必查清单
| 检查项 | 说明 |
|--------|------|
| 网络请求超时 | 必须设置 timeout |
| 下载失败降级 | 必须有 fallback 路径 |
| SSL/证书验证 | HTTPS 也需完整性校验 |
| 重试/幂等性 | 考虑网络抖动场景 |

### 2. 临时资源生命周期审查
```
□ 临时文件创建位置
□ 是否注册清理回调
□ 异常路径下是否泄漏
□ 进程终止时的清理
```

### 3. 复杂度阈值警告
```
当新增代码 >30 行 且 包含以下任一特征时：
- 网络操作
- 文件系统操作
- 线程相关
→ 自动触发完整审查（非 quick 策略）
```

## 二、下载/字体类 Issue 规范

### 4. 字体下载安全必查
- HTTPS 链接 + 完整性校验（SHA256）
- 超时机制 + 失败降级策略
- 临时文件清理（不用 delete=True 依赖）

### 5. 字体类 Issue 分析要点
- 字体加载失败**根因分析**（路径/依赖/格式支持）
- CJK 渲染特殊需求
- 回退策略有效性验证
- 必含标签：`PIL/pillow`, `font`, `style`, `layout`

## 三、Issue 分析质量红线

### 6. 分类准确性
- `bug`：功能完全不工作/崩溃
- `enhancement`：体验优化/功能未达期望
- ❌ 不能将"期望未满足"误标为 `bug`

### 7. 标题改写规范
- ❌ 禁止添加 `[bug][medium]` 等分类前缀
- ❌ 禁止越权判断分类
- 原标题异常时直接改写内容，**不添加前缀**

### 8. 标签-分类一致性
- 分类修正后必须**同步调整标签**
- `bug` 分类 → `bug` 标签；`enhancement` → 移除 `bug` 标签

### 9. 截图引用（规范红线）
```
截图查看清单：
□ 是否包含截图？字体特征？
□ 与期望的差异点？
□ 是否所有文字都受影响？
```
- 未引用截图 = 分析质量不合格

### 10. 标签完整性要求
PIL/字体类 Issue 必含：`PIL/pillow`, `layout`, `style`, `beginner`
UI 调整类：必含 `beginner`

## 四、评分与决策一致性

| 评分 | 应匹配 | 问题 |
|------|--------|------|
| 6/10 | 多个中高风险 | 若仅 1 个简单 bug → 评分过低 |
| 9/10 | 完整覆盖全维度 | 存在未审查区域 → 评分虚高 |

**教训**：评分应反映**实际发现的问题数量和严重程度**，而非仅依赖问题修复难度。

## 五、敏感操作边界检查

```
□ 资源获取：是否有竞态条件
□ 资源释放：异常路径是否也会释放
□ 网络操作：超时、重试、失败处理
□ 文件操作：权限、空间、路径遍历
□ 配置依赖：硬编码值是否有配置化需求
```

## 六、模式识别清单

| 模式 | 风险 | 审查要点 |
|------|------|----------|
| 搜索链模式（paths遍历） | 回退逻辑遗漏 | 验证每个分支都有兜底 |
| 回退下载模式 | 网络+临时文件 | 安全校验+清理机制 |
| 临时文件+delete=True | 异常路径泄漏 | 显式清理逻辑 |

---

**核心原则**：quick 模式不应跳过**安全敏感操作**审查，字体下载/网络请求属于此类。
