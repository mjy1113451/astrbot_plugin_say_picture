## 一、Issue 分析核心规范

### 1.1 截图/附件处理（硬性要求）
- **必须查看并引用**：分析报告中必须明确回答"截图是否查看？"
- 期望元素位置需从截图确认，修改边界需覆盖截图内容
- 违反此要求属于**严重违规**，可能导致误判

### 1.2 置信度管理
| 场景 | 调整规则 |
|------|---------|
| 图片 Issue 视觉解读 | 整体下调 0.05-0.10（存在不确定性） |
| 模糊需求 | 下调至 0.75-0.80 |
| 标签与项目核心功能相关 | 如 `image-generation` 对本项目应提升至 0.95 |

### 1.3 标题改写规范
- **禁止行为**：添加 `[分类]` / `[优先级]` 前缀（越权行为，分类应由人工确认）
- **允许行为**：内容补充、去除无意义字符、保留原始信息完整性
- **判断标准**：原标题已清晰时，**不为改写而改写**
- 原始标题异常（如仅标点）时，标注"标题异常，基于正文内容分析"

### 1.4 优先级独立判断
- 不盲目采纳 Issue 作者的自评优先级
- 建议调整标准：
  - 功能受影响 → 维持作者评级
  - 纯 UI 调整 + 极简单修改 → 可降级至 `low`
  - 影响核心功能 → 升级优先级

## 二、标签体系规范

### 2.1 必含标签维度
Issue 标签应覆盖 **类型 + 领域 + 难度** 三个维度：

| 维度 | 常见标签 | 说明 |
|------|---------|------|
| 类型 | enhancement, bug, feature | 分类标签 |
| 领域 | image-generation, UI, font, PIL/pillow | 技术领域 |
| 难度 | beginner, good-first-issue | 可选，降低门槛 |

### 2.2 本项目常见标签
```
enhancement, image-generation, UI, font, PIL, style, layout, 
good-first-issue, beginner, display
```

### 2.3 遗漏常见标签
- **UI 标签遗漏率高**：字体大小/布局调整类 Issue 应补充 `UI` 或 `display`
- **PIL 相关**：涉及绘图修改时补充 `PIL` / `pillow`
- **风格/布局**：`style`、`visual`、`layout` 常被遗漏

## 三、可行性判断规范

### 3.1 基础要求
- 提供**具体文件 + 行号**（如 `main.py 第 104-162 行`）
- 给出**代码片段或伪代码**，避免纯文字描述
- 明确**工作量估算**及依据（如"1 行修改"）

### 3.2 边界检查清单（PIL/坐标类 Issue 必查）

```
□ 水平边界：文字宽度是否超出容器
□ 垂直边界：元素高度变化是否影响间距（与相邻元素的关系）
□ 对齐关系：修改后是否保持元素对齐
□ 坐标基准：是否基于固定尺寸气泡框
□ 文字溢出：缩小 UI 后对长文本的处理能力是否下降
```

### 3.3 坐标联动检查
UI 尺寸调整类 Issue 不仅关注被调整元素，还需检查**相邻元素**：
- 缩小头像 → 气泡框起始 X 坐标是否需要左移？
- 文字区域宽度是否需要重新计算？

### 3.4 字体相关风险
- 中英文混合文字宽度比例差异
- 多行文字换行处理（`textwrap` 或 `font.getsize`）
- 字体回退机制（跨平台字体差异）
- 新版 PIL API 变化（`ImageFont.getsize` 已弃用，改用 `.getbbox`）

## 四、重复检测规范

### 4.1 检索策略记录
必须明确记录以下信息：
```
检索词：layout, 样式, 排版, bubble, 气泡, text-wrap
检索范围：astrbot_plugin_say_picture 仓库全量 Issue
结果：无重复
```

### 4.2 检索关键词组合日志
```
检索: "LV100" + "字体" + "字号" → 0 结果
检索: "LV100" + "大小" → 0 结果
```

### 4.3 结论明确性
- **禁止模糊表述**："可能是 #22 的重复" → 必须明确判断
- 正确做法：
  1. 引用 #22 标题/内容，说明相似点
  2. 明确判断：`duplicate` / `not duplicate` + 理由
  3. 若无法确认，标记为「需人工确认」

## 五、模糊需求处理

### 5.1 识别标准
- 用户未明确说明当前痛点
- 仅描述期望效果（如"更像图片这种排版"）而无具体参数
- 标题无意义（如仅"."）

### 5.2 处理方法
1. **置信度统一下调 0.10**
2. **明确标注「待用户确认」清单**：
   ```
   □ 具体目标尺寸？
   □ 当前问题是什么？
   □ 是否有参考示例？
   ```
3. 可行性判断增加"最小可验证方案"要求

## 七、项目特定注意事项

基于 `astrbot_plugin_say_picture` 仓库特点：

1. **核心依赖**：PIL/Pillow 绘图是核心功能
2. **固定画布**：气泡框坐标基于固定尺寸，调整时需重新计算所有相对位置
3. **字体渲染**：中英文混合场景多，需考虑宽度差异
4. **跨平台**：Windows/macOS/Linux 字体路径差异
5. **API 兼容性**：注意 PIL 版本差异导致的 API 变化
