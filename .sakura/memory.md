# AstrBot 插件代码审查经验积累

**累计反思 7 次**

---

## 一、Issue 分类与优先级

### 1. 分类准确性
- 标题含 `[bug]` 关键词时**必须识别为 `bug`**，不能误分为 `other`
- 功能请求/UI改进 → `enhancement` / `feature request`
- 功能缺陷 → `bug`
- 空标题时：**依赖摘要内容判断分类**，不能放弃

### 2. 优先级评估
| 场景 | 建议优先级 |
|------|-----------|
| 核心功能失效（表情包无法使用） | high / medium |
| UI 布局微调 | medium / low |
| 非紧急优化项 | low |

---

## 二、标签推荐质量

### 1. 标签体系建议
| Issue 类型 | 推荐标签 |
|-----------|---------|
| 字体/渲染问题 | `font`、`chinese`、`i18n`、`rendering` |
| 图片生成 | `image-generation` |
| UI 调整类 | `UI`、`display`、`enhancement` |
| 简单改动 | `beginner`、`good-first-issue` |

### 2. 置信度评估
- 仅基于标题关键词 → 0.7-0.85（不宜 0.95）
- 有代码依据 + 查看截图 → 0.85-0.90
- 图片 Issue 存在解读不确定性，置信度应适度下调

### 3. 降级策略
- **摘要生成失败时** → 使用关键词提取备用方案
- **标签提取失败时** → 不能放弃，应依赖摘要关键词补充标签
- 置信度过低时 → 给出"基于不完整信息的推断"

---

## 三、可行性判断质量

### 1. 关键要求
- 引用具体代码行号和文件位置
- 提供明确坐标值（避免"例如"、"可能"等模糊表述）
- 区分代码定义值 vs 推断值
- **增加"修复完整性"评估维度**

### 2. 跨平台兼容性（字体问题必查）
| 平台 | 常见中文字体路径 |
|------|-----------------|
| Windows | `C:/Windows/Fonts/simhei.ttf`、`msyh.ttc` |
| macOS | `/System/Library/Fonts/PingFang.ttc` |
| Linux | 需 fontconfig 查询 |

### 3. UI/坐标类 Issue 必查项
- [ ] **截图必须查看**，明确说明"已查看附件确认期望位置"
- [ ] **目标位置具体化**：给出参考坐标或说明需与用户确认
- [ ] 边界检查（文字宽度超出容器怎么办）
- [ ] 多语言文本长度差异（自适应位置）
- [ ] 配置化可能性（用户自定义位置）
- [ ] 此修改是否影响其他元素布局
- [ ] **文字大小是否需要调整以适应新位置**

### 4. 图片类 Issue 特殊处理
- 提取信息时注明"**基于图片内容推测**"
- 图片Issue存在信息损耗，不宜过度推断

---

## 四、重复检测

- 使用关键词组合检索（如 `字体` + `渲染` + `中文`）
- 明确说明检索策略
- UI 位置调整类通常独特，重复概率低

---

## 五、标题改写

| 场景 | 处理方式 |
|------|---------|
| 空标题/无效标题 | **必须改写**，基于摘要生成 |
| 标题已清晰准确 | 保持原样或适度精简 |
| 需强调类型 | 格式：`[type][priority] 核心描述` |

**注意**：改写应有价值，**不能与原标题完全相同**，需体现分析的专业性。

---

## 六、附件处理

- 有截图时：**必须查看并引用具体位置**
- 图片 Issue：注明"基于图片内容推测"
- 说明当前问题位置 vs 预期效果

---

## 七、常见错误避免

| 问题 | 教训 |
|------|------|
| 分类失败 | 标题含 `[bug]` 却未识别 → 强化关键词匹配 |
| 摘要生成失败 | 协议标签未过滤 → 添加内容安全过滤层 |
| 置信度虚高 | 仅基于标题给 0.95 → 需适度保守 |
| 沿用原标签 | 应独立分析后给出判断，再与原标签对照 |
| 坐标不一致 | 建议坐标前后矛盾 → 确保表述统一 |
| 分析中断放弃 | 标签/摘要失败直接放弃 → 启用降级策略 |
| UI风险低估 | UI调整类风险被低估 → 需考虑视觉一致性 |

---

## 八、仓库特有经验

这是一个 **AstrBot 图片生成插件**，涉及 PIL 绘图，未来可能遇到：
- 多个文本/元素坐标联动调整
- 不同字体大小适配
- 多语言文本边界情况
- 气泡框、LV100 等 UI 元素的布局调整

---

## 九、分析检查清单

完成分析后对照检查：
- [ ] 是否查看了所有附件（截图、日志等）？
- [ ] 是否识别了可能的一对多关系（一个 Issue 包含多个功能点）？
- [ ] 可行性评估是否考虑了边界情况和国际化？
- [ ] 是否考虑了可配置性而非纯硬编码？
- [ ] 是否提供了具体的坐标建议或需与用户确认？
