## 核心规范

### Quick 模式升级条件
| 触发条件 | 强制升级为完整审查 |
|----------|-------------------|
| 行数 > 30 | ✅ |
| 涉及坐标计算/布局变更 | ✅ 强制 |
| 涉及数学运算 ≥5 步 | ✅ 建议 |
| 首次全量审查 | ✅ 强制 Full |

### 首次全量审查特别要求
1. 策略不得降级为 Quick/Fast
2. 必须记录：项目核心功能、入口、潜在风险区
3. 变更排查范围覆盖所有相关标识符（非仅 diff 部分）

## 经验教训

### 1. 布局/UI 变更审查要点
```
□ 代入至少 3 组具体数值验证坐标计算
□ 检查气泡高度变化时的行为（0、正常、极端）
□ 验证相关联 x/y 坐标同步更新
□ 极端长度测试（单字符 / 50+ 字符）
□ 多语言兼容性（ASCII / CJK / Emoji）
```

### 2. "一致性" ≠ "正确性"
- Quick 模式通过一致性检查 ≠ 逻辑正确
- 涉及坐标计算的变更：必须验证计算公式本身

### 3. 修复类 PR 审查清单
```
□ 问题是否只出现在这一处？
□ 搜索所有相关标识符，排查遗漏（如 badge_tw vs _badge_tw）
□ 修复是否引入新变量名的一致性问题？
```

### 4. Issue 分析规范
- 方括号标签 `[enhancement][low]` 应正确解析：第一个→分类，第二个→优先级
- 技术性失败 ≠ 无法评估：应重试或标记"待人工处理"
- 标签为空时应触发警告

### 5. Quick 模式决策树建议
```
行数 ≤ 30 + 无复杂计算 → Quick
但需验证：无复杂计算链路（≥5步数学运算需补充说明）
```

## 代码模式库

| 模式 | 风险 | 建议 |
|------|------|------|
| 变量覆盖（同一作用域重复赋值） | 隐蔽陷阱 | 标注风险 |
| 坐标魔法数字（-10、+16 等） | 低 | 考虑常量抽取 |
| 文字居中 vs 左对齐 | 需验证实现 | 建立描述→代码映射 |
